## #1. DB가 만들어지지 않음 — `ERROR 1049 Unknown database 'cobot'`
- **일시**: 2026-11-17 (화) 18:30 이전, 서버 PC
- **상황**: 계정 생성 SQL과 `sudo mysql < rokey1/db/schema.sql`을 실행한 뒤 확인했다
- **증상**
  ```
  mysql -u cobot -pcobot cobot -e "SHOW TABLES;"
  ERROR 1049 (42000): Unknown database 'cobot'
  ```
- **확인한 것**
  | 항목 | 결과 |
  |---|---|
  | MySQL 서비스 | active |
  | `cobot`@`%` 로그인 | 됨 |
  | 권한 | `GRANT ALL PRIVILEGES ON cobot.*` 있음 |
  | `SHOW DATABASES` | information_schema, performance_schema만 있음 |
- **원인**: `rokey1/db/schema.sql`은 상대경로라서 `~/ws_cobot_pjt/ws_dsr/src`에서 실행해야 한다. 다른 폴더에서 실행하면 파일을 못 찾아 아무것도 만들어지지 않는다
- **해결**: 절대경로로 다시 실행
  ```bash
  sudo mysql < ~/ws_cobot_pjt/ws_dsr/src/rokey1/db/schema.sql
  ```
- **결과**: `command, gap, task_log, wall` 4개 생성을 확인했다 (이후 migrate_01 적용으로 6개)
- **재발 방지**: 문서에 있는 명령은 모두 절대경로로 적는다

## #2. 접속 거부 — `ERROR 1045 Access denied`
- **일시**: 2026-11-17 (화) 18:30 이전, 서버 PC
- **증상**
  ```
  mysql -u cobot -p cobot -e "SHOW TABLES;"
  Enter password:
  ERROR 1045 (28000): Access denied for user 'cobot'@'localhost' (using password: YES)
  ```
- **확인한 것**: 같은 시각에 `mysql -u cobot -pcobot ...`로는 정상 접속됐고 테이블 4개도 보였다 → 계정과 DB는 정상이다
- **원인**: 비밀번호를 잘못 입력했다. 입력해도 화면에 보이지 않아서 **한/영 키가 한글 상태**면 다른 글자가 들어간다
- **참고**: `-p cobot`처럼 띄어 쓰면 `cobot`은 비밀번호가 아니라 **DB 이름**으로 해석된다. 비밀번호를 붙여 쓰려면 `-pcobot`
- **해결**: 영문 상태에서 다시 입력하거나 `-pcobot`을 사용한다

## #3. 매니저가 공정 노드를 못 찾음 — `E_NO_SERVER` (ROS 탐색 서버 설정)
- **일시**: 2026-11-17 (화) 18:30 ~ 18:34, 서버 PC
- **경과**
  | 시각 | 내용 |
  |---|---|
  | 18:30:50 | `ros2 launch .../manager.launch.py fake:=true` 실행 → 매니저 `state: IDLE`, rosbridge 9090 정상 |
  | 18:31:19 | `INSERT INTO command (cmd) VALUES ('START')` |
  | 18:31:22 | command 1 → **FAILED**, task_log에 `EXPLORE / explore_result / success=0 / E_NO_SERVER` |
  | 18:3x | 원인 조사 |
  | 18:33:34 | `unset ROS_DISCOVERY_SERVER ROS_SUPER_CLIENT` 후 launch 다시 실행 |
  | 18:34:01 → 18:34:07 | command 2 → **DONE**, task_log 6줄 (EXPLORE → PUTTY → SANDING) 정상 |
- **증상**
  - 매니저가 3초 안에 `/process/explore` Action 서버를 찾지 못했다 (같은 launch 안에 fake_process가 떠 있었는데도)
  - 다른 터미널에서 `ros2 node list`, `ros2 action list` 결과가 비어 있었다
- **조사 방법**: 실행 중인 fake_process 프로세스의 환경변수를 확인했다
  ```bash
  tr '\0' '\n' < /proc/<PID>/environ | grep -E "ROS_|RMW"
  # ROS_DOMAIN_ID=11
  # ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
  # RMW_IMPLEMENTATION=rmw_fastrtps_cpp
  # ROS_DISCOVERY_SERVER=172.24.0.136:11811   ← 원인
  ```
  ```bash
  grep -n "ROS_DISCOVERY_SERVER\|ROS_SUPER_CLIENT" ~/.bashrc
  # 135:export ROS_DISCOVERY_SERVER=172.24.0.136:11811
  # 136:export ROS_SUPER_CLIENT=TRUE
  ping -c 2 172.24.0.136     # 100% packet loss
  ```
  (이 PC의 IP는 172.24.2.211)
- **원인**
  - 135~136줄은 이전 프로젝트(터틀봇, 바로 위에 `TURTLEBOT3_MODEL=burger`가 있음)에서 쓰던 **FastDDS 탐색 서버(Discovery Server)** 설정이다
  - 이 설정이 있으면 모든 노드가 **172.24.0.136의 탐색 서버를 통해서만** 서로를 찾는다
  - 그 서버가 응답하지 않아서 **같은 PC 안의 노드끼리도 서로를 못 찾았다**
  - 같은 코드, 같은 PC에서 이 두 변수만 해제했더니 바로 정상 동작 → 원인이 확정됐다

  | ROS2 노드 탐색 방식 | 동작 | 조건 |
  |---|---|---|
  | 기본 (멀티캐스트) | 같은 네트워크에 알리고 서로 찾음 | 같은 `ROS_DOMAIN_ID`, 같은 네트워크 |
  | 탐색 서버 (135~136줄) | 정해진 서버에 등록하고, 그 서버에 물어봐서 찾음 | 그 서버가 **켜져 있고 접속 가능해야** 함 |
- **임시 해결 (적용함)**: launch를 띄우는 터미널에서만 해제
  ```bash
  unset ROS_DISCOVERY_SERVER ROS_SUPER_CLIENT
  ```
  → 그 터미널에만 적용된다. **새 터미널을 열면 다시 문제가 생긴다**
- **영구 해결 (⚠️ 아직 적용 안 함 — 팀 결정 후 적용)**: `.bashrc` 135~136줄 주석 처리
  ```bash
  sed -i 's/^export ROS_DISCOVERY_SERVER=/# export ROS_DISCOVERY_SERVER=/; s/^export ROS_SUPER_CLIENT=/# export ROS_SUPER_CLIENT=/' ~/.bashrc
  # 적용 후 새 터미널을 열고 확인
  env | grep -E "ROS_DISCOVERY_SERVER|ROS_SUPER_CLIENT"    # 아무것도 안 나오면 정상
  ```
  - 지우지 않고 `#`만 붙인다 → 나중에 탐색 서버가 필요하면 `#`만 빼면 된다
  - 주석 처리가 필요한 이유: 매니저, 공정 노드, bringup, rosbridge 등 **모든 노드가 영향을 받는다**. 터미널마다 `unset`을 하다 하나라도 빠뜨리면 그 노드만 안 보이는데, 이런 문제는 원인을 찾기가 아주 어렵다
- **대안 (탐색 서버를 계속 쓰기로 할 경우)**: 주석 처리 대신 아래처럼 맞춘다
  - 서버 PC에서 항상 실행: `fastdds discovery --server-id 0 --port 11811`
  - **모든 PC**의 `ROS_DISCOVERY_SERVER`를 서버 PC의 IP로 바꾼다 (172.24.0.136 아님)
  - Wi-Fi 공유기가 멀티캐스트를 막아서 PC끼리 서로를 못 찾을 때 해결책이 된다 → **먼저 기본 방식으로 해 보고, 안 되면 이 방식으로 바꾸는 것을 추천**
- **같이 확인할 것**
  - 팀원 PC의 `.bashrc`에도 같은 설정이 남아 있는지 (`grep -n "ROS_DISCOVERY_SERVER" ~/.bashrc`)
  - `.bashrc`에 `ROS_DOMAIN_ID`가 두 번 있다 (128줄 `10`, 138줄 `11`). 마지막 값인 **11**이 적용된다. 모든 PC에서 최종 값이 같아야 한다
