rokey1 실행 순서

터미널에서는 빌드 · DB 확인 · 웹 HMI만 띄웁니다. 웹에서 sodvir / sodreal로 로봇을 연결하고, 공정을 골라 ▶ 시작을 누르면 필요한 액션 서버는 HMI가 알아서 켭니다. 탐색 → 틈 하나씩 퍼티·샌딩 → 전체 공정 순서로 확인하세요. 체크 박스는 이 브라우저에만 저장됩니다.

실제 로봇을 움직이기 전에처음 실행은 속도 30~50%, 하드웨어 비상정지 버튼을 손 닿는 곳에 두세요. 웹의 비상 정지는 소프트웨어 정지일 뿐입니다. 모드는 누른 버튼(sodvir = 가상, sodreal = 실제)으로 정해지고 액션 서버도 같은 모드로 켜집니다. 터미널에서 bringup을 따로 띄웠다면 그 mode와 웹에서 누른 버튼이 같은지 직접 확인해야 합니다.

A터미널 준비 (서버 PC)

  1. 빌드 — 모든 팀원 PC에서 한 번

    액션 메시지(Process.action)에 wall 필드가 있습니다. 한 PC라도 옛 빌드면 액션 통신이 안 됩니다.

    cd ~/ws_cobot_pjt/ws_dsr
colcon build --paths src/rokey_interfaces src/rokey1
source install/setup.bash

    src/rokey1_/rokey1도 패키지 이름이 rokey1이라 --packages-select rokey1은 "이름 중복"으로 실패합니다. 위처럼 --paths로 빌드하거나, rokey1_ 폴더를 지우거나 그 안에 빈 COLCON_IGNORE 파일을 두세요.

  2. DB 접속 확인

    접속 정보는 config/robot.yaml의 db 섹션입니다.

    mysql -u cobot -pcobot cobot -e "SHOW TABLES;"   # run, wall, gap, task_log, quality

  3. 웹 HMI 서버

    ros2 launch rokey1 process.launch.py host:=0.0.0.0     # 다른 PC에서도 접속
# 로봇 없이 DB 흐름만: ros2 launch rokey1 process.launch.py fake:=true

    브라우저 주소: http://<서버 PC IP>:8080. 로봇 bringup은 터미널에서 띄우지 않아도 됩니다(B-2에서 웹 버튼으로).

    혼자 가상 시험할 때 (권장) — 기본 설정은 Wi-Fi 너머 원격 discovery server를 거쳐 bringup이 수십 초~수 분 걸립니다. HMI를 띄우기 전에 같은 터미널에서 한 줄씩:

    unset ROS_DISCOVERY_SERVER ROS_SUPER_CLIENT
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
env | grep -E 'DISCOVERY|SUPER|RANGE'   # RANGE=LOCALHOST 한 줄만 나와야 함

    이 HMI가 띄우는 bringup · 서버도 같은 설정을 물려받아 수 초 안에 연결됩니다. 대신 다른 PC와 ROS 통신은 안 됩니다(웹 접속은 됨). 터미널에서 bringup만 띄울 때는 sodvir_local. 따로 여는 터미널(ros2 run 등)도 같은 설정을 해야 bringup이 보입니다.

B웹 HMI에서

  1. 화면 연결 보기

    맨 위 연결 칩이 초록(서버 연결됨)인지 봅니다. 상단 조작 바의 모드 칩은 아직 bringup 꺼짐이고, ▶ 시작 · ⌂ 홈은 눌리지 않는 상태(bringup 필요)가 정상입니다.

  2. 로봇 연결: sodvir / sodreal

    상단 조작 바에서 가상이면 sodvir, 실제 로봇이면 sodreal(컨트롤러 192.168.1.100). ~/.bashrc의 같은 이름 alias와 같은 명령(m0609_rg2_bringup bringup.launch.py)을 HMI가 실행합니다.

    몇 초 뒤 모드 칩이 가상 · bringup 연결됨(실제면 빨간색 실제 로봇)으로 바뀌고 시작 버튼이 켜집니다. bringup 출력은 실시간 작업 현황 → 로그의 로봇 bringup 탭에만 나옵니다(작업 로그와 섞이지 않음, 경고 팝업도 안 뜸).

    터미널에서 이미 bringup을 띄웠다면 버튼을 눌러도 bringup을 또 띄우지 않고 화면 모드만 바꿉니다(모드 칩: 외부 bringup).

  3. 속도

    조작 바의 속도 슬라이더를 처음엔 30~50%로 낮춥니다. 실행 중에도 바로 적용됩니다.

  4. 탐색

    공정 탭 → 탐색 → 파라미터 입력 → ▶ 시작. 탐색 액션 서버가 꺼져 있으면 HMI가 먼저 켜고(상태 띠에 액션 서버 켜는 중) 준비되면 바로 시작합니다. 로봇이 바닥 → 벽 → 높이 → 너비를 찍어서 잽니다.

    끝나면 작업 로그에 wall_id=… · gap_id=[…]가 찍힙니다. 이 gap_id를 적어 두세요. 비어 있으면 robot.yaml의 explore.gaps에 틈 좌표를 넣고 다시 탐색합니다(틈 자동 감지는 아직 없음).

  5. 틈 하나로 퍼티 → 샌딩

    공정 → 퍼티 → 틈 번호 (gap_id)에 위 번호 → 시작. 끝나면 같은 번호로 샌딩. 퍼티·샌딩 서버도 처음 시작할 때 자동으로 켜집니다(샌딩은 RG2 /onrobot 필요). 샌딩은 그 틈의 벽 4점으로 벽 방향을 계산하고, 누르는 힘은 robot.yaml force.sanding.press_force 값을 씁니다.

  6. 전체 공정

    공정 → 전체 공정. 꺼져 있는 서버(탐색·퍼티·샌딩)를 모두 켠 뒤 탐색 → 틈마다 퍼티 → 틈마다 샌딩 순서로 진행하고, 실패하면 그 자리에서 멈춥니다(재시도 없음).

  7. 결과 보기 · 멈추기

    실행 기록에 결과(OK / STOP / E_xxx)가 남습니다. 멈출 땐 ■ 정지, 위험하면 비상 정지(Esc) → 원인 해결 후 RESET.

  8. 현황 화면 보조 기능

    실시간 작업 현황 탭:

    · TCP 작업 공간 오른쪽 위 경로 보기 / 좌표 보기 — 위에서 본 TCP 이동 경로, 또는 로봇 자세 그림 + 위치·자세·관절 6좌표. posx 복사로 현재 x, y, z, a, b, c를 복사해 샌딩의 시작/종료 posx 칸에 붙여 넣을 수 있습니다.

    · 로그 — 작업 로그 / 로봇 bringup 탭, 정보·경고·오류 필터, ⧉ 전체 복사(보고 있는 탭 전체를 복사, 문제 보고할 때 붙여 넣기).

숫자 칸은 칸 아래 설명에 범위(예: 1 이상 · 정수)가 나오고, 비우거나 범위를 벗어나면 시작할 때 어느 칸이 왜 틀렸는지 알려 주고 실행하지 않습니다. 이미 켜진 액션 서버나 bringup이 다른 모드면 공정 시작이 막힙니다. 파라미터 영역 오른쪽 위 ↺ 기본값으로 버튼으로 되돌릴 수 있고, 기본값에서 바뀐 칸은 강조 표시됩니다. 틈 번호 외의 입력값은 브라우저에 저장돼 다음에도 남아 있습니다.
