- util: 특이점 관리(`singularity.py`), 카메라 위 유지(`camera_up.py`) — 뼈대만 작성

## 3. 상태값 / 오류 규칙 (manager.py `POLICY`)
상태값: IDLE / RUNNING / ERROR / ESTOP (`/manager/state` 토픽으로 방송)

| 코드 | 재시도 | 이후 대응 |
|---|---|---|
| E_GRIP | 1 | HOLD (그 자리 정지, START 대기) |
| E_FORCE | 1 | HOME (대기 자세로 복귀) |
| E_SINGULAR | 0 (재시도는 util 안에서) | HOME |
| E_TIMEOUT | 0 | HOLD |
| E_NO_GAP | 0 | SKIP (이 틈만 건너뜀) |
| 알 수 없음 / 서버 없음 | 0 | HOLD |

## 4. DB 테이블 (rokey1/db/schema.sql, 6개)
```
command ─(cmd_id = run_id)─ run (1) ──< wall (1) ──< gap (1) ──< task_log   (동작 기록, 매니저)
                                                          └──< quality    (공정별 점수, 웹)
```
| 테이블 | 단위 | 주요 칸 | 쓰는 쪽 |
|---|---|---|---|
| `command` | 명령 1개 | cmd(START/STOP), status, **purpose, material, note** | 웹 INSERT, 매니저 status 갱신 |
| `run` (11/17 저녁 추가) | 실행 1번 | purpose(TEST/EXPERIMENT/DEMO), material(putty/clay), code_version(git 해시), started_at, ended_at, result | 매니저 |
| `wall` | 벽 1개 | top / floor / right / left 각 xyz, run_id | 매니저 |
| `gap` | 틈 1개 | start / end xyz, wall_id FK | 매니저 |
| `task_log` | 세부동작 1번 | step, **attempt**, success, **error_code**, fail_reason, gap_id, joint / task / force_val, **params, contact_ratio, force_stats, started_at**, duration_ms | 매니저 |
| `quality` (11/17 저녁 추가) | 틈 1개 × 공정 1개 | score(1~5), depth_mm, rater, note. (run_id, gap_id, task_code) 중복 불가 | 웹 |

- 식별코드는 AUTO_INCREMENT. run_id는 command의 cmd_id를 그대로 쓴다
- 칸 구분 원칙: 실험 분석에서 `GROUP BY`/`WHERE`에 자주 쓰는 값(contact_ratio, error_code, attempt)은 따로 칸, 공정마다 항목이 다른 값(params, force_stats)은 JSON
- 기존 DB 변경: `migrate_01.sql` (11/17 18:4x 서버 PC에 적용 완료, 기존 데이터 유지)

1. **실험 계획**: 목표 힘 3단계 × 속도 3단계 = 9개 조합, 조합마다 3번 → 27회. 아이클레이로 진행

   → 표만 봐도 가장 좋은 조합이 보인다 (이것만으로 "데이터 기반 파라미터 선정"이라고 발표할 수 있다)
3. **모델** (pandas + scikit-learn, DB에서 바로 읽음):

4. **반영**: 고른 값을 robot.yaml에 넣는다 → 코드 수정 없이 재시작 → 다시 기록 → 개선됐는지 비교

### 분석 SQL 예시
```sql
-- 파라미터 조합별 성공률·접촉 유지율·품질
SELECT t.params->>'$.target_fz' AS fz, t.params->>'$.vel' AS vel,
       COUNT(*) n, AVG(t.success) ok, AVG(t.contact_ratio) contact, AVG(q.score) score
FROM task_log t
JOIN run r ON r.run_id = t.run_id AND r.purpose = 'EXPERIMENT' AND r.material = 'clay'
LEFT JOIN quality q ON q.run_id = t.run_id AND q.gap_id = t.gap_id AND q.task_code = t.task_code
WHERE t.step = 'putty_scrape' AND t.attempt = 0
GROUP BY fz, vel ORDER BY score DESC;

-- 오류 코드별 횟수
SELECT task_code, error_code, COUNT(*) FROM task_log WHERE error_code IS NOT NULL GROUP BY 1, 2;
```
